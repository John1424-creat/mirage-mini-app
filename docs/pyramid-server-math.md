# Серверная математика Пирамиды

## Статус

Версия математики: `pyramid-v1`.

Сервер уже определяет результат одного раунда Пирамиды. Клиент пока не подключён к API и продолжает работать в демонстрационном режиме. До подключения клиента серверный и клиентский расчёты нельзя смешивать.

## Вход раунда

- ставка: целое число от `5` до `10 000` рубинов с шагом `5`;
- линии: от `8` до `16`;
- риск: `low`, `medium` или `high`;
- кошелёк: `real` или `demo`;
- обязательный `Idempotency-Key` длиной от 8 до 128 символов.

## Определение результата

1. Сервер валидирует ставку и конфигурацию до изменения баланса.
2. Слот выбирается криптографически безопасным RNG по откалиброванному распределению Matter.js из клиента.
3. Коэффициент рассчитывается из профиля риска и масштабируется к непрерывному RTP `95%`.
4. Выплата равна `round(stake * multiplier)`.
5. Сервер формирует путь из `rows` решений, сумма которых равна целевому слоту. Путь предназначен только для визуализации.
6. Раунд, списание ставки, выплата и ledger фиксируются одной PostgreSQL-транзакцией.

## Проверка

- 15 серверных тестов проходят;
- проверены все 27 сочетаний линий и риска;
- непрерывная модель даёт ровно `95%` для каждой конфигурации;
- прогон по `1 000 000` раундов на каждую конфигурацию при ставке `100` дал диапазон `94.688%–95.337%`;
- точный RTP после целочисленного округления при ставке `100` находится в диапазоне `94.864%–95.240%`.

## Открытый математический вопрос

При маленькой ставке один рубин является слишком крупным шагом округления:

- ставка `5`: точный округлённый RTP по конфигурациям находится примерно в диапазоне `90.55%–98.45%`;
- ставка `10`: примерно `93.42%–97.50%`.

Это не ошибка RNG, а эффект формулы `round(stake * multiplier)` при целочисленном балансе. До реального запуска надо выбрать и независимо проверить один вариант:

1. хранить более мелкую внутреннюю денежную единицу;
2. создать отдельные целочисленные payout-таблицы для малых ставок;
3. изменить минимальную ставку и набор коэффициентов.

Текущая `pyramid-v1` сохраняет совместимость с клиентской формулой и не считается финальной сертифицированной математикой для реальных денег.
